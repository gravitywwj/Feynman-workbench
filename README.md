# 费曼学习工作台

一个面向自主学习者的本地 Web 工作台。它将个人 Markdown Wiki、主动回忆、费曼式讲解、盲区修订和间隔复习串成可持续的学习流程。

项目优先保存你的学习数据与资料控制权：学习记录、笔记、复习计划和反馈均默认存放在本机；LLM 能力为可选增强，不配置密钥也可以使用基础学习流程。

## 适合做什么

- 从本地 Wiki 的某个知识点开始学习，并用自己的话完成一次讲解。
- 保存讲解、待澄清点和学习心得，回看自己的理解如何变化。
- 用复习计划安排主动回忆，或使用“突击检查”快速检验薄弱点。
- 让复习卡回到 Wiki 原文：每张新卡保留资料摘录、必备要点和原文定位，而非把第一次讲解当成标准答案。
- 在知识点页完成固定标准的应用、变式和延迟自测，或记录课程作业与平台练习。
- 按学习领域查看可筛选、可拖动的知识图谱，再回到具体笔记继续学习。

## 开始使用

以下步骤以 Windows 为例。命令中的路径均为示例，请替换成你电脑上的实际位置。

1. 获取代码并进入项目目录。

   ```powershell
   git clone https://github.com/gravitywwj/Feynman-workbench.git
   cd Feynman-workbench
   ```

2. 创建 Python 虚拟环境并安装依赖。

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

3. 在项目根目录创建本地配置文件。

   ```powershell
   Copy-Item .env.example .env
   ```

4. 启动工作台。

   最方便的方式是双击项目根目录的 [start.bat](start.bat)。脚本会检查服务是否已经运行；需要时在后台启动服务，并在就绪后打开浏览器。

   也可以在终端中运行：

   ```powershell
   .\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001
   ```

5. 打开 [http://127.0.0.1:8001/](http://127.0.0.1:8001/)，并在“设置”中选择资料库或体验演示资料。

## 按问题安排学习

选中资料后，在“本次学习”记录一个具体问题、理解变化和下次起点。默认参考时长为约 60 分钟，可在本次编辑中延长，也可在设置中修改默认值。阅读、回忆、应用和整理可随时进入，时间用于参考；复杂问题可以跨天接续。

保存后，首页优先接续这个问题，复习仍可独立进入。切换重点资料或归档时，已有问题与断点保留到“学习记录 → 学习心得”。保存的重点随学习数据备份；导入时已有其他重点，备份中的断点保留为心得。顶栏“今日回忆用时”只统计回忆会话记录。

## 准备你的资料库

工作台读取的是 **Wiki 根目录**，而不是单个 Markdown 文件。这个目录至少需要包含一个 `pages` 子目录；页面可以继续按主题建立子文件夹。

```text
我的学习资料库/                  ← 在“设置”中选择这一层
├─ pages/                         ← 存放 Markdown 学习页面
│  ├─ 人工智能/
│  │  └─ 提示词工程.md
│  └─ 金融基础/
│     └─ 现金流.md
└─ assets/                        ← 可选：图片、附件等资料
```

你可通过两种方式指定这个目录：

- 在网页的“设置”中选择本地资料库；选择结果只保存在本机。
- 在 `.env` 中设置 `FEYNMAN_WIKI_PATH`，适合固定部署或启动脚本使用，例如：

  ```dotenv
  FEYNMAN_WIKI_PATH=C:\Users\你的用户名\Documents\我的学习资料库
  ```

## 可选：启用 LLM 辅助

不填写 API 密钥时，工作台仍提供表达线索、本地复习和固定标准的应用自测。离线表达反馈不能确认知识事实；仅有可靠参考资料且由学习助手依据资料核对通过的记录，才计入来源核对。

如要获得基于参考资料的追问、批改和诊断，可在 `.env` 中填写兼容 OpenAI API 格式的服务信息。当前变量名沿用 `DEEPSEEK_`，但模型名称和服务地址由你自行选择：

```dotenv
DEEPSEEK_API_KEY=你的_API_密钥
DEEPSEEK_BASE_URL=https://你的服务地址/v1
FEYNMAN_LLM_MODEL=你的服务所提供的模型标识
```

例如，若所用服务提供 `deepseek-v4-flash`，可将它填入 `FEYNMAN_LLM_MODEL`；这只是一个模型标识示例，并非使用本项目的前提或唯一选择。请确认所选服务与模型支持 OpenAI 兼容的聊天接口。

也可以在网页的“设置 → 学习助手 API”中保存多个连接，例如 DeepSeek、Agnes 或本地模型服务。网页不会回显密钥；它仅保存在当前设备的 `data/llm-settings.json`，不会随学习数据导出，也不会写入 Wiki。网页中已启用的连接优先于 `.env`，可一键切换；`.env` 仅在尚未启用网页连接时作为首次启动或无界面部署的备用配置。点击“测试当前连接”时才会向所选服务发送一次最小请求，最近连通结果会显示在对应连接上。

## 数据与隐私

- 本地学习记录默认保存在 `data/feynman.db`（SQLite）。
- 工作区设置保存在 `data/workspace-settings.json`。
- 通过网页保存的 API 配置存放在 `data/llm-settings.json`，该文件已排除在 Git 之外。
- 学习数据导出使用版本 7，旧版本 1–6 仍可导入；导出包含当前学习问题、断点和自测记录，不包含 API 设置或密钥。
- Wiki 原始资料始终由你本地目录管理；阅读状态等必要元数据可能按你的操作写回页面 frontmatter。
- 若启用 LLM，提交给服务的是当次学习所需的资料片段与输入内容。请根据所用服务的隐私政策决定是否使用。

## 学习后的想法与 Wiki 写回

复习会话只用于独立复述、诊断和纠错，不会自动改写 Wiki。学习笔记可生成知识草稿；学习后另有想法时，用“想法讨论”多轮推敲。两条路径的最终草稿都须先点“审核草稿”，查看原始资料摘录、审核判断和拟修改的页面差异，再由你确认写回。

写回只针对已有的 Learning Wiki 页面：原始资料支持的结论进入“学习增量”，证据不足的推论进入“待验证问题”，明显错误的草稿不能写入。没有关联页面的想法保留在本地；工作台暂不自动建页、摄入新资料或写入 personal-wiki。新资料与独立概念仍由 Wiki 目录中的 Agent 按其规则维护。

写回要求所选学习根目录有 `pages/`、`index.md`，且同目录或父目录有 `SCHEMA.md` 和 `log.md`。工作台会更新页面日期、索引日期、追加操作日志；若有 `scripts/lint_wiki.py`，还会运行现有 Wiki 校验。页面或原始资料在审核后发生变化时，须重新审核。撤销会恢复页面和索引，并追加一条撤销日志。

内置演示 Wiki 不具备完整维护文件，只用于练习；试用写回时应选择 `D:\LLM wiki\learning-wiki`。

最终审核若启用外部 AI，会发送你编辑的草稿及目标页面声明的最多三段 Learning Wiki `raw/` 摘录（每段最多 2200 字符；很短的资料可能全部包含在摘录中）；不会读取 personal-wiki 内容。未启用 AI 时只可标记为待验证，不能自动判定事实正确。

建议定期备份 `data/` 目录和你的 Wiki 根目录；两者共同构成完整的个人学习档案。

## 学习证据与复习核对

回忆表达不再以“写够多少字”为通过条件。开始诊断前，选择 2 到 3 项可观察的理解证据：定义或目标、因果机制或步骤、具体例子或场景、适用边界或条件；可同时标记自己最不确定的一点，下一步追问会优先围绕它展开。离线反馈只整理表达线索，不判断答案是否符合事实；无法核对时明确显示“待核对”。

新建复习卡从当前 Wiki 的标题和正文要点生成。复习时先独立作答，再查看资料摘录、必备要点，或点击“回原文定位”。只有学习助手启用、卡片保存了可靠出处、回答依据原文核对并通过时，才记录“来源核对”；本地关键词匹配与无资料回退都显示“待核对”，不会给出伪参考答案。

知识点页的“应用自测”提供两组固定题目：精确率/召回率计算，以及工具调用参数与白名单校验。结果按明确标准逐项判定，可记录练习、首次应用、不同题目的变式和间隔七日的延迟结果。页面按证据类别分别展示表达与来源核对、应用、变式和延迟结果，不计算跨领域总分。题目检验计算与规则理解，不会执行代码或证明程序已通过外部平台判题。

外部课程作业和平台练习只保存用户填写的链接、结果、帮助程度与可选提交文本，并标为“用户自报，未自动核验”。工作台不登录平台、不抓取题目、不代替用户提交，也不运行代码。应用自测结果与来源核对、复习排程相互独立。

掌握状态遵循证据层级：`未接触 → 已接触 → 能回忆 → 已核对 → 保持中`。其中“已核对”至少需要一次来源或明确标准核对；“保持中”需要在至少 14 天内的不同日期多次通过来源核对。阅读次数和自评评分会安排复习节奏，但不会单独升级为掌握结论。

待处理盲区会按“概念缺失、因果链错误、边界条件遗漏、例子迁移失败”归入可执行的小型纠错路径：先做一次约两分钟的微练习，隔天再用不同情境复测，最后才进入来源核对。首页的下一步推荐可参考考试日期、今日可用时间、章节权重、当前把握度和近期错误类型，并说明推荐原因、预计用时与完成收益；周报则展示反复错的概念簇、从待澄清到来源核对的证据，以及下周最少的 1–3 个优先项。

## 关联阅读与 Wiki 维护

首页和知识点侧栏的“接着读什么”结合当前学习问题、近 30 天的回忆表达、个人笔记、心得、未解决的诊断提示和固定练习核对结果，按 Wiki 链接及共同关键词推荐最多 3 篇已有笔记，并展示依据。阅读推荐不会改变学习重点或掌握状态；没有学习记录时仅参考明确标记在读、已读的页面。这里使用本地链接和关键词匹配，没有调用外部模型。

“待补充主题”收集当前问题、不确定点、未解决的提示、固定练习错误和近期学习页的缺失链接，并列出关键词匹配到的已有覆盖。学习疑问不等于 Wiki 缺失：维护 Agent 先读已有页面，再按 Wiki 规则核查一手来源、补充原页或新增主题。“导出 Wiki 维护清单”生成本地 Markdown 文件。

维护 Agent 每次运行时可在本项目目录读取最新需求，工作台网页无需运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m app.services.learning_recommendations
# 结构化数据
.\.venv\Scripts\python.exe -X utf8 -m app.services.learning_recommendations --json
```

网页运行时也可读取 `GET /api/study/recommendations` 与 `GET /api/study/recommendations/brief`。需求实时从本地记录计算，不单独维护队列。本功能不创建定时任务；维护周期由 Wiki Agent 的运行安排决定。清单包含学习问题和笔记线索，按本地学习档案保存。

## 项目目录

```text
app/                  FastAPI 应用代码
├─ routers/           页面资料、学习会话等 HTTP 接口
├─ services/          Wiki 解析、复习计划、LLM 辅助等业务逻辑
├─ static/            浏览器学习界面
└─ demo_wiki/         内置演示资料库
data/                 运行后生成的本地数据库与工作区设置（不提交）
tests/                API、服务与浏览器功能流程测试
obsidian-plugin/      可选的 Obsidian 配套插件
start.bat             Windows 快捷启动脚本
```
